01 / Current conclusion

A three-source stack is the likely answer

Separate archival research data, live market data and broker execution. One product is unlikely to be best at all three.

Research base

SET / SEC official data for security master, EOD prices, corporate actions, filings and point-in-time fundamentals.

Intraday archive

SET SMART Marketplace when we need authoritative trade ticks, historical bids/offers or licensed snapshots.

Live + execution

Settrade Open API through a supported broker for live bars/book, account state and order lifecycle.

TISCO constraint. The current Settrade broker matrix marks both stock and TFEX Open API as unavailable for TISCO. The existing account is suitable for manual Streaming, but not the public retail API. Keep TISCO if desired; use a second, API-enabled broker for automation. Official broker matrix.

For engineers: continue with the plain-language database, crawler, scheduler and trading-platform design.

06 / Example use cases

What the stack should make possible

Disclosure reaction study

Join a SET/SEC release timestamp to 1-minute bars and a SET50 benchmark; measure 5m, 30m, close and next-day abnormal return.

Inputs: filing timestamp · 1m bars · index bars · security master

Fundamental screen without look-ahead

Rank liquid SET/mai shares on value, quality and revisions using only statements available on each simulated date.

Inputs: PIT fundamentals · filings · EOD prices · corporate actions · delisted names

Liquidity-aware intraday signal

Trade only when spread, displayed depth and recent volume are acceptable; estimate slippage from tick/book history before promotion.

Inputs: live 10-level book · bars · historical trades/book · market status

Paper-to-live execution

Generate an order, pass broker risk checks, monitor partial fills/cancels and reconcile positions after reconnect—without changing strategy logic.

Inputs: Settrade order/account APIs · fills · cash/positions · immutable order IDs
07 / Outside-team research brief

Questions that decide the vendor/broker choice

Request written answers and sample payloads. Product pages are not enough for architecture or licensing decisions.

Coverage & identifiersSET/mai, common/ETF/DR/DW, NVDR/foreign, suspended and delisted names; stable ID across symbol changes.
History & point-in-timeFirst date, exact intraday retention, filing publication time, restatements, original vs adjusted values.
Microstructure fidelityTrade ticks vs snapshots; auction prints; order-book depth, sequence, corrections, timezone and session labels.
Operational limitsRequests/minute, max subscribed symbols/connections, reconnect/replay, SLA, maintenance windows and gap-fill.
Trading differencesBroker eligibility, fees/minimums, order/validity types, credit/short rules, sandbox realism, PIN/key expiry and rejects.
LicenseInternal storage, backtesting, derived metrics/models, screenshots, external reports and raw/derived redistribution.

Ask each serious candidate for the same sample

  1. AOT, PTT and CPALL: one year of raw EOD plus all corporate actions and an adjusted series.
  2. The same names: 20 sessions of 1-minute bars and one complete day of trades + book, including open/close auction.
  3. Ten years of quarterly fundamentals with the original publication timestamp, revisions and one restatement example.
  4. One suspended/delisted security to demonstrate historical-universe coverage and identifier continuity.
  5. Sandbox order lifecycle: place, partial fill, change, cancel, reject, reconnect and final portfolio reconciliation.
