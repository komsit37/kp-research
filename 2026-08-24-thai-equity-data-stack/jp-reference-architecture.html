For platform and data engineers

Japanese stock platform: the reference for Thailand

The Japanese system already separates company documents, clean market data and scheduled jobs. Thailand should keep this same shape: build new country connectors, reuse the shared platform, and avoid mixing broker execution into research services.

01 / System in one minute

Three services have clear jobs

Document planeJPS

“JP Stock Filings.” Downloads EDINET and TDnet documents, stores originals, extracts useful content, and provides search, API and command-line access.

Structured data planeRook + PostgreSQL

Loads prices, company facts, symbols, events and other tables from J-Quants, JPX and supporting sources. Tracks each pipeline run and data freshness.

Orchestration planeDagu

Runs both systems on market schedules. It handles retry, overlap protection, catch-up, logs and job history.

Main design rule: JPS owns documents; Rook owns query-ready tables; Dagu owns when work runs. PostgreSQL and bulk file storage are shared infrastructure, not business logic.

04 / Data ownership

Know where a bug belongs

JPS owns the evidenceOriginal company documents, their metadata, extracted text and document search.
Rook owns clean factsRows used in screens and models: prices, symbols, financial facts, events and source freshness.
Dagu owns the runWhen a job starts, what it depends on, retry rules, logs and final status.
Consumers own decisionsResearch notes, alerts and orders. They read data but do not alter source history.

Example: a missing filing is a JPS connector issue; a stale closing-price table is a Rook job issue; a job that never started is a Dagu issue.

05 / Operating rhythm

A normal Japanese market day

Times are representative current schedules in Japan time. Weekly and seasonal jobs run around this daily core.

00:05
TDnet end-of-day: finish the index, disclosure digest, segment extraction and theme links.
00:07
EDINET index: collect the prior publication day’s regulatory filing list.
07:30
Document monitoring: EDINET watch and filing-change digests run on their scheduled days.
08:00–15:35
TDnet intraday: poll every five minutes and create disclosure digests.
16:00–23:00
TDnet after hours: continue hourly checks for later releases.
18:00
Rook prices: update J-Quants daily prices after market data is ready.
18:30
Rook company data: refresh listed-company master and financial summaries.
18:40
Supporting snapshot: refresh selected Yahoo quote-summary fields on weekdays.
Weekly
Slow-changing data: refresh JPX symbols, filing search indexes, embeddings and other broad indexes.

Shared defaults include skip-on-overlap, a six-hour catch-up window, three retries and retained run logs. Jobs should be safe to run again for the same date.

07 / Improvements while copying

Keep the design; remove Japan-only shortcuts

ChangeWhy it mattersMinimum implementation
Universal instrument IDJapan currently relies heavily on the four-digit security code. Thai symbols and future multi-market data need a neutral key.instrument_id plus market, local symbol, effective dates and source aliases.
Raw-to-row lineageA clean row should point back to the exact file or API reply that created it.Add raw_object_id, checksum, parser version and ingestion run ID.
One run contractJPS and Rook have good run controls, but their metadata is not yet one universal format.Standard fields for source, market date, start/end, watermark, row count, error and freshness.
Market-qualified timeThailand and Japan have different zones, calendars and sessions.Store source time, received time and UTC; schedule from a versioned market calendar.
Clear source precedenceLive, official daily and fallback values can disagree.Keep each source separately; publish a documented rule for the preferred research view.
Do not clone the databases row for row. Reuse the service boundaries, Go connector pattern, PostgreSQL operations and Dagu controls. Design Thai tables around stable multi-market IDs and stronger lineage from day one.
08 / Build sequence

A practical hand-off to the outside team

Thai document planeProve one SEC source and one SET disclosure source. Save originals, metadata and publication time; make both searchable.
Thai Rook adaptersLoad security master, daily prices, actions and basic fundamentals with stable keys, raw lineage and freshness checks.
Dagu operationsAdd Bangkok-time DAGs, market calendar, backfill, retry, overlap rules, alerts and a one-page freshness view.
Live then paperRecord Settrade data for a full week, measure gaps, then connect a supported broker sandbox through the separate order service.

Definition of done for the first review: working source-access proof, proposed schemas, sample raw objects, replayable loads, Dagu job list, freshness results, expected storage/load, license notes and known gaps.
